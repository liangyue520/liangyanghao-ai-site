# 两份 AI 工具账单，为什么不能只比价格

周一早上，同事问起刚续费的 AI 编程工具。一个人说花了 760 元，另一个人说自己只花了 690 元。两人都把它叫作“Codex Pro”，平时也都用来读项目和写代码，自然会问：为什么差了 70 元？

这里的 760 元和 690 元是文中假设的账单金额，不代表当前官方标价。只凭这两个数字，还不知道两个人买的是否相同，也不能确定差价来自哪里。要比较，得先打开各自的官方订阅页面和实际订单。

## 同样说“买了账号”，可能在说不同的东西

以前买开发工具，通常先看官网价格，合适就买。高频使用 AI 编程工具后，讨论中开始出现更多问题：

- 用的是哪一种订阅方案？
- 是个人开通，还是公司分配的席位？
- 费用对应一个月、固定天数，还是其他周期？
- 额度如何计算，什么时候重置？
- 买的是产品订阅，还是 API 调用额度？
- 能不能报销？

有时几个人讨论了半天，才发现一个人在说个人订阅，一个人在说组织采购的席位成本，还有一个人在说按量调用的费用。大家都说自己“在用 AI 写代码”，买到的权益却不相同。

因此，报出价格之前，最好先说明产品、方案和费用周期。否则一个人拿月度总额，另一个人拿使用几天的账单，数字低并不意味着同一项服务更便宜。

## 先确认“Codex Pro”具体指什么

“Codex Pro”可能是日常交流中的简称。实际核对时，应查看官方页面中产品和订阅方案的完整名称，确认自己的账号究竟有哪些 Codex 使用权益。

不要仅凭聊天里的“Plus”“Pro”或截图上的几个字，就认为权益一定相同。个人方案、组织提供的席位和 API 计费可能属于不同体系，具体可用范围与限制需要逐项核对。[OpenAI Codex 官方页面](https://openai.com/codex/)和[ChatGPT Pro 方案说明](https://help.openai.com/en/articles/9793128-what-is-chatgpt-pro)可以作为查阅入口，实际购买金额和权益则以对应账号的官方结账页面及订单为准。

核对时，把产品页面、当前账号与订单放在一起看。名字相似时，先确认具体方案，再比较账单，不能仅凭常见简称换算人民币价格。

## 760 元和 690 元，应该怎样对账

回到这两份假设账单，能够确定的只有总额相差 70 元。解释差价之前，可以逐项检查。

方案是否相同。除了名字，还要核对实际档位、可用功能、额度与适用账号，避免把看起来相似的名称当成相同权益。

周期是否相同。首次付款、续费、按月与固定天数的订单，可能没有相同的起止日期。比较时应先统一周期，再看费用。

付款方式是否相同。查看订单是通过官方网页还是对应应用商店结算，账单由谁管理，后续续费和取消应在哪里操作。不要根据一张报价图推断费用构成。

币种和结算时间是否相同。最终支付记录可能涉及不同币种和结算时点，核对时应看订单列明的项目。关于支持的币种及网页、应用商店订阅的付款说明，可以查看[OpenAI 多币种付款说明](https://help.openai.com/en/articles/10421635-multi-currency-billing-faq)。

是否有额外费用。如果支付记录包含其他收费，就应确认收费内容和提供方。不能在看不到订单时，直接把 70 元解释为汇率、活动或服务费。

对完这些信息，才有条件讨论谁的支出更低。在此之前，更有用的问题是：“你的这笔费用具体对应什么？”

## 都能用来写代码，也未必有相同的使用体验

两个人可能都说，平时主要用工具改代码、看项目。进一步聊下去，一个人通常一次处理一个小任务，另一个人经常读取较多代码、排查接口并运行较长的任务。

即使使用同一方案，感受到的“够不够用”也可能不同。任务大小、上下文长度、模型和功能，都会影响使用情况。一个简单的页面修改，和反复读项目、运行命令、检查失败再修复的流程，不能直接按任务个数相比。

购买或续费之前，可以先回看自己的实际使用：

- 是偶尔解释代码，还是每天都参与开发？
- 主要处理明确的小修改，还是上下文较多的任务？
- 遇到额度限制的频率有多高，影响了哪些工作？
- 限制出现后，能否接受等待或调整任务安排？
- 当前账号的使用记录，是否支持升级或维持方案的判断？

同事说“足够用了”，只能说明他的使用体验。它可以作为了解工具的起点，不能代替自己的任务记录。

## 个人订阅、API 和组织席位要分别计算

假设旁边另一位同事说：“我这个月只花了几十块。”大家以为找到了更便宜的相同方案，追问后才发现，他说的是项目调用 API 的费用。

个人订阅对应一定周期内的产品权益；API 按对应服务的计费规则结算；组织席位则可能由公司统一管理，适用相应采购和使用安排。它们都和 AI 开发有关，但直接比较月度总额，无法判断哪一种更适合。

这有点像比较月票和按次乘车。必须先看实际频率、使用范围和所需功能，才能算清费用。

个人订阅中的 Codex 使用权益，也不能直接理解为同等金额的 API 调用余额。如果项目要调用 API，应单独确认账单、预算和相关权益；遇到特定活动或额度说明，还要核对适用资格。

## 价格之外，还要确认账号和数据的归属

比较费用时，账号是谁持有、谁能够访问，也很实际。开发工具中的内容可能包括对话记录、项目代码、连接的仓库、团队资料，以及付款信息。

如果有人要求提供密码、验证码或开放账号访问，不能因为报价更低就忽略这些问题。公司代码和客户资料应使用公司允许的账号与服务，账号使用和凭据管理应核对服务方的规则。

对工作账号，至少应该弄清：谁拥有和管理账号，谁能查看相关内容，离职或更换人员时怎样处理，出现付款或访问问题由谁解决。具体使用限制可继续核对[OpenAI Pro 方案说明](https://help.openai.com/en/articles/9793128-what-is-chatgpt-pro)。

这些问题不需要等出了故障再讨论。便宜 70 元很容易被看见，账号访问和资料处理范围却同样会影响实际使用。

## 工作工具费用，应该由谁承担

再往下聊，两个同事都说工具是自己付费的。平时既用于学习，也用于公司项目；有时因为项目急、额度不足，又临时增加投入。

如果工具已经成为完成工作的重要条件，值得和公司确认是否统一采购、提供席位或允许按需报销。各家预算和制度不同，不能预设所有个人订阅都能报销，但可以先整理清楚：

> 主要用它完成哪些工作？  
> 公司现有工具为什么不够？  
> 额度限制具体影响过什么任务？  
> 能否提供符合项目与数据要求的方案？

带着具体任务和使用情况讨论，比只报一个月花了多少钱，更容易说明需求。个人学习或自己的项目，则应结合个人预算决定投入多少。

## 最后还要看，这个月用它解决了什么

发现自己比同事多花 70 元，第一反应可能是“买贵了”。核对账单之外，也可以回看工具在真实任务里有没有帮助。

如果只是看到别人升级，担心自己落后，却很少使用，可以重新评估方案。如果每天用它理解项目、定位问题、减少重复工作，这些帮助也值得纳入判断。不过，频繁使用同样不能证明每次都有效：有些任务省了时间，有些任务可能在反复沟通和返工中花得更多。

续费前，回看任务结果、额度限制和费用，再决定维持、调整或停止。示例里的两个人最终没有只凭 760 和 690 下结论，而是先对照自己的订单。

“多少钱”值得问，“我们买的是不是同一项权益”也得问清楚。
